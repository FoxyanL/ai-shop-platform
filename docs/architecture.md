# Архитектура проекта

## Сервисы

- **Storefront**: Next.js App Router с TypeScript, серверной загрузкой опубликованного каталога и metadata для SEO.
- **Admin**: React + Vite + TypeScript. Redux Toolkit хранит сессию и состояние административных разделов; service worker и manifest обеспечивают PWA-оболочку.
- **API**: Koa + TypeScript. Маршруты версии `/api/v1`, PostgreSQL через `pg`, Redis для временных кодов и сессий, Redis Streams для событий каталога и заказа.
- **Infrastructure**: Docker Compose для локальной разработки и Kubernetes-манифесты, применимые в k3s.

## Данные

PostgreSQL — источник истины для аккаунтов, новостей, брендов, размеров, категорий, товаров, методов оплаты и доставки, получателей, корзин, чекаутов и транзакций. Бизнес-сущности имеют `createdAt` и `updatedAt`. Категории связаны через `parentId`; товары — через `categoryId`, `brandId` и размеры. Поле `shopId` связывает данные с магазином платформы.

Redis хранит одноразовые коды и вращаемые refresh-сессии с TTL. События, нужные другим частям системы, публикуются в Redis Streams; межсервисное обращение не связывается синхронно с записью критичных данных.

## Доступ

Публичная витрина читает только опубликованные товары. Операции административного CRUD требуют access-токен и роль администратора или владельца магазина. Получатели и корзина всегда фильтруются по `userId`; идентификатор из URL сам по себе не даёт доступ к чужим данным.

## Запуск и выпуск

Каждый исполняемый сервис собирается своим Dockerfile. Compose включает API, storefront, admin, PostgreSQL и Redis. K8s-манифесты содержат Deployments, Services, ConfigMaps, Secrets-шаблон и probes; реальные секреты добавляются вне репозитория.
